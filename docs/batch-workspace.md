# 按批文件工作区

## 使用方式

每个任务明确选择一组来源余额、税务资料和开票模板。原始文件保持不变；试算和生成的 Excel 是本批候选结果。用户可以直接查看输入和输出的工作表，再人工决定采用或作废。采用后可从本批剩余资料继续创建下一批，不必把剩余表作为独立新增资金重复导入共享账簿。

本功能独立于原来的正式共享账簿。`processing_*` 表保存文件任务、版本和操作事件；原有 `allocation_workspace`、独立双审和正式入账凭据保持原有语义。按批任务的“人工采用”记录操作者对文件的选择，不会生成两份虚构的核验报告，也不代表旧账簿已经正式入账。

## 数据与状态

- 结构化资料、参数、任务状态、文件哈希及上下批关系存入 SQLite 索引与不可变 JSON 对象。
- 原始 XLSX、税务修正 JSON 和生成的 XLSX 存入现有对象文件目录，按 SHA-256 校验，不覆盖原件。
- 状态依次为草稿、候选结果和人工采用；草稿或候选可作废并保留记录。
- 修改与采用携带 revision。旧窗口操作被拒绝，避免覆盖另一窗口的更新。
- 采用结果的下游资料链受到约束；已有有效下游任务时，不能直接作废父批并让后续文件失去依据。
- 新工作区不读取生产资料作为演示数据，不自动迁移旧正式账簿。

## 数据预览

从本批已登记的文件选择工作表，以分页和行号查看数据。预览仅展示文件已有数值、文本与公式缓存，不执行宏或公式；公式没有缓存时应明确显示。长账号和税号按原始文本保留，预览不能恢复原文件已经丢失的数值精度。搜索和分页以服务端返回的范围为准。

## AI 助手

AI 由服务端调用 DeepSeek；浏览器不会获得密钥。支持连续问答、需求参数草稿与当前批次辅助预检。助手只能读取经过权限检查的本批摘要，应用商品参数需要用户点击确认。金额规划、来源守恒和组余额限制由现有整数分引擎执行。

模型上下文只包含界面明确说明的必要摘要，不自动上传整份原始工作簿。辅助预检应说明实际覆盖范围，不能代替独立财务审计。无配置、取消、限流、超时或模型响应异常时保留人工处理路径，不显示虚构成功。

服务端兼容 `DEEPSEEK_API_KEY` 或受限密钥文件；可通过 `DEEPSEEK_MODEL` 和服务地址配置选择模型。现有部署的密钥继续留在服务器，不复制到开发目录。生产配置见网站运行文档。

## 本地验证与上线边界

项目位于 D 盘时，安装依赖前把 TEMP、TMP、TMPDIR、npm cache 和其他可控缓存指向 D 盘。开发数据、截图、合成文件和日志留在忽略的 `.work/`、`site/work/` 或指定 D 盘任务目录。不要在源码中提交数据库、客户文件或密钥。

上线前需要通过精确分摊回归、权限和并发测试、候选文件独立核对、AI 协议测试及真实浏览器验收。数据库迁移只新增按批任务表。任何正式共享余额的迁移或线上发布均是独立操作，必须有可审核结果和对应授权。
