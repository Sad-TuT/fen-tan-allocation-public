# 分摊网站

分摊网站按批次管理重新上传的余额、税务主体资料、商品开票模板、结果文件和历史记录。计算使用整数分，申领人、成本中心、法律主体及用途必须完整一致；只有申领部门和使用中心同时非空且逐字相同才能合并，任一字段为空的来源行必须单独成组。网站不保存共享余额，也不自动沿用上一批余额。

## 工作流程

1. 使用网站账号登录并新建批次。
2. 每个新批次都要重新上传本次准备使用的资金表；支持一次多选或拖拽，最多10份、每份不超过10 MB。所有资金表等权参与选组，先满足金额和余额规则，再尽量少用开票行。选定跨来源同组后，按来源编号和原行顺序记账，以便分别生成每份表的已用和剩余结果。同时上传税务主体表和开票模板。
3. 填写商品、单价和数量后先精确试算，再生成候选文件。候选区可以逐份下载文件，也可以点击“一键保存全部”下载本批 ZIP；解压后的文件夹名为“时间-产品名称-花费金额”。申领部门或使用中心为空的来源行按自身金额独立试算，网站不补填部门，也不允许该行与其他记录合并。
4. 核对本批开票单、各来源标红表、剩余表和核对记录。
5. 确认本批完成后，系统只保存本批状态和文件，不会自动带入余额。下一批请重新上传你核对后确定要用的资金表；如果沿用本批资金，必须用本批生成并核对过的剩余表，防止重复计算。

每个批次导入税务修正 JSON 时，每条修正只能选择一种作用范围：指定批次使用 `scope.batch_ids`；明确授权未来批次则使用 `scope.applies_to_all_future_batches:true`，并提供带时区的 `scope.effective_from_utc`。两种范围不能同时声明。网站会把批次创建时间与该起点比较，过去批次不会套入后来才生效的修正。本批上传的税务主体表和税务修正文件只作为本批输入。

## 运行和测试

- Node.js 需支持 `node:sqlite`，建议使用 22.21 或更新的受支持版本。安装依赖：`npm ci`。
- `npm test` 运行分摊、开票、权限和批次测试；`npm run test:ai` 运行 AI 兼容测试。`npm run build:server` 构建 Node/Next.js 服务，`npm run start:server` 以本机地址启动服务。
- 设置 `ALLOCATION_DATA_DIR` 为应用目录以外的绝对路径；程序会在其中建立 SQLite 数据库和对象文件。管理员账号须在服务器本机使用 `scripts/initialize-owner.mjs` 初始化；脚本从标准输入读取账号信息，不要把账号密码写入命令历史或仓库。
- 登录限流密钥通过 `ALLOCATION_RATE_KEY_FILE` 指向的受限文件提供。文件应归运行账号所有，不能进入 Git 仓库。生产环境可参考 `scripts/server-pm2.config.cjs`。
- DeepSeek 功能可选配置 `DEEPSEEK_API_KEY` 或 `DEEPSEEK_API_KEY_FILE`；也可在数据目录的 `secrets/deepseek-key` 放置受限密钥文件。默认模型为 `deepseek-flash`，可使用 `DEEPSEEK_MODEL` 覆盖，API 地址可通过 `DEEPSEEK_API_BASE_URL` 配置（兼容 `DEEPSEEK_API_BASE`）。
- AI 助手只读取本批结构化摘要；只有用户主动勾选后，本轮才会附带文件预览中的少量单元格。不会自动发送整份工作簿。AI 结果仅供参考，不能替代人工核对和确认。
- 通过 HTTPS 对外服务时，设置 `ALLOCATION_PUBLIC_ORIGIN` 为正确的 HTTPS 源，并由可信反向代理验证主机名、覆盖转发头和配置证书；如有多个严格受控入口，可用英文逗号分隔完整 HTTPS 源，任何空项、非 HTTPS 或带路径/账户的无效项都会让公网入口整体拒绝。Node 服务继续仅监听本机。
- Next.js 在独立部署时会发送 CSP、HSTS、`nosniff`、禁止嵌入、Referrer Policy 和 Permissions Policy 等完整安全响应头。若可信公网入口已经统一发送其中由入口负责的响应头，可设置 `ALLOCATION_EDGE_SECURITY_HEADERS=true`；应用会避免重复，同时通过页面 CSP meta 保留脚本和样式等细粒度限制，并继续发送 `X-Frame-Options`、`Cross-Origin-Opener-Policy` 和 `Cross-Origin-Resource-Policy`。上传接口在完整解析前限制请求体，并最多同时处理两份 XLSX/JSON；超限请求返回明确的 413 或 429，避免复杂压缩文件占满 Node 主进程。
- `scripts/allocation-backup.mjs` 可按环境变量指定的数据和备份目录创建备份，并检查 SQLite/对象引用及恢复流程。生产环境应按当天分摊节奏执行备份。备份必须与源码和凭据分开保护，并复制到独立机器或对象存储。

本仓库仅提供代码和合成测试，不提供账号、密钥、客户数据或历史账簿。旧规则或旧共享账簿页面只保留数据库审计痕迹，不再作为资金来源。所有新批次都以当次上传的余额表为准。
