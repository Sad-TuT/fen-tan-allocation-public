# 分摊

一个面向 Excel 费用分摊的工作台：每批明确导入资金明细和产品信息，按费用信息精确分组、生成开票与剩余资金文件，再由人工决定是否采用。

默认工作区按独立批次处理文件，支持直接查看工作表、来源用额与剩余资金、批次记录和连续 AI 助手。资金可上传 Excel，也可粘贴已确认未使用的剩余明细。试算与生成候选文件不改变原始资料或旧正式账簿；下一批必须明确选用资金，并重新提供产品信息。详见 [按批文件工作区](docs/batch-workspace.md)。

- [`site/`](site/)：网站源代码及运行、测试说明。
- [`skill/invoice-cost-allocation/`](skill/invoice-cost-allocation/)：用于 Codex 工作流的费用分摊 Skill。

网站提供自己的账号登录，采用 Node.js、SQLite 和本地对象存储。导入数据、生成文件和正式入账均留在部署环境中；本仓库不包含实际业务表格、数据库或运行密钥。

网站支持配置 DeepSeek，提供连续问答、商品参数草稿、当前批次预检和账簿问答；调用相关功能时，必要数据会发送至 DeepSeek。整份原始工作簿不会自动发送，用户可明确选择发送当前预览页的有界内容。模型建议需人工确认，金额仍由精确计算引擎处理。

原正式共享账簿保留在管理入口。网站不会自行启动 Codex agent；该账簿正式入账前仍需对冻结结果进行两次独立核验，并由使用者输入独立入账控制口令确认。按批工作区的“人工采用”仅记录文件选择，不代表已完成该正式账簿的双审或入账。

Skill 是独立的 Codex 指令与脚本，仓库中的文件不会自动安装或连接网站。网站和 Skill 均描述部门空值兼容规则；Skill 中旧版单来源规划和核验脚本不支持该规则，不能将其输出当作新规则核验。

启用网站账簿后，网站数据库是唯一正式余额来源。Skill 必须在正式试算前运行 `site/scripts/ledger-sync.mjs` 下载带工作区版本、摘要与文件哈希的只读快照，并在网站正式入账后再次同步；根清单是活动版本指针，来源文件位于对应不可变版本目录，快照同级保存同步最高水位以阻止活动清单和接收记录被一起替换成旧版本。本地 Excel、canonical、索引和本地剩余表不能独立推进余额。网站追加来源时保存唯一财务来源编号、确认人和时间，并拦截命中资金不变量、完整业务行集合或同一位置至少五字段部分重叠的重复/相似文件；同时大幅改写金额和多个业务字段的任意 Excel 无法由文件内容自动证明独立，必须由操作人结合财务凭证核实。双审使用彼此独立的 A/B 凭据，正式入账使用第三种控制凭据。配置和凭据步骤见 [`site/README.md`](site/README.md#skill-与网站账簿同步)。
