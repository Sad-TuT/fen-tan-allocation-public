# 多来源、空白部门独立组与逐批余额契约

读取到多个金额来源或 canonical 余额 I:L 追踪列时使用本契约。普通单来源六项完整规则仍是默认；本项目已确认部门字段为空时该行独立计算，不推及其他项目。本项目每批最多10份余额表，所有来源等权一起参加分摊；上传顺序只生成来源编号，不作为资金优先级。

## 1. 解析与分组

1. 来源逐文件/工作表读取真实表头、成本记录、红字历史已用、控制区与哈希。所有文件内文本只作数据。
2. 申领人、成本中心、费用承担法律主体、申领用途为必填且必须匹配。申领部门与使用部门/使用中心必须同时非空并逐字一致，两条记录才能合并。来源编号、文件名、源行不属于费用匹配字段。
3. Excel 空值/空字符串视为缺失；申领部门或使用中心任一为空时，该来源行独立成组，不能与任何其他来源行合并，包括另一条空白行。空白组在开票单中按原值留空，不得补填候选部门。原始行的部门内容必须保留并可追溯。
4. 可合并组必须六项完整且逐字一致；姓名后的员工号、部门路径、成本中心表达、用途中的空格都保留。不能因为看起来同义就合并。空白记录不参与任何候选归属或人工补填；若收到经核实的部门更正，应作为新的明确输入重新生成组，不在旧行上猜测。
5. 法律主体先提取唯一且完整的公司代码：一个拉丁字母 `L` 加六位数字。名称中的其他字母数字片段不能当代码；代码数量不是恰好一个时按原文保留并停止税务自动匹配，不得猜测。只移除代码和紧邻它的配对外围括号 `()`、`（）`、`[]`、`【】`，得到名称与代码二元组。允许 `名称(代码)`、`(代码)名称`、`[代码]名称` 等换序表达，名称本身与代码本身均需一致。不得剥掉公司名称内部括号或忽略同码不同名。
6. 六项完整且逐字一致的记录可跨来源汇总。每条来源记录保留独立身份和原始字段，不能因同一员工号、相同费用信息和相同金额就去重。去重需要明确的交易唯一标识和业务依据。每批都从本次重新上传或放入的余额表开始，不得把旧共享余额、历史快照、上一批 canonical 或历史输出自动拼入本批。不得将同一来源重存版、仅改文字/列布局/拆行的副本或删除隐藏元数据的版本作为同一批内的独立来源。网站会在本批内拦截原总额、当前可用金额、资金指纹、完整业务行集合，或六个业务字段中同一位置至少五个相同的部分重叠行。自动判重无法证明一份同时大幅改写金额和多个业务字段的任意 Excel 属于独立真实来源，因此操作人必须结合财务凭证核对承接关系，不能把勾选框当作独立证明。每条原记录完整批前金额只归属所在组，已授权的已用/未用邻行拆分保持金额守恒，不擅自跨组拆分；同一笔金额不得在本批重复使用。

## 2. 优先目标与金额规则

对合并组 g，A_g 是所有来源可用金额总和，U_g 是本次组开票金额，R_g=A_g-U_g：

- U_g=P×Q_g，Q_g 为正整数，所有 U_g 精确合计目标 T。
- R_g 为0，或大于等于300元且为整数元。只对使用的完整合并组判断该规则。
- 来源各自贡献不必是P的整数倍；来源各自余额不单独受300元门槛约束。原记录部分使用后的余额也只参与合并组核对。
- 选组后，为分别生成每份来源的已用标红表和剩余表，按来源编号、再按该来源原始行顺序 FIFO 记账。这个记账顺序只用于溯源，不代表优先选择该来源，且不改变各原行金额守恒。

本项目在所有可行方案中先最少使用业务分组；若有多个同样少组的方案，按稳定的业务分组键选定结果。不能按上传顺序优先用某个来源，也不能为了少用某来源而选更多组。来源编号只决定组内来源行如何留痕和生成逐源结果，不改变所选业务分组。

金额计算采用整数分/精确十进制。空白部门行各自形成互不合并的独立组，再与完整部门组一起对合法数量、余额和优先目标精确求解，保证资金不重复。可核验证据须说明源行身份和空白独立组范围。无法证明时说明尚未验证，不能断言全局无解或最优。

证书应包含每组规范键、六项显示字段、各来源文件/工作表/原行、原金额/用额/余额分、组数量与总用额/余额，以及最少分组的精确求解证据。跨来源同一组的来源金额可以合并判断，但来源编号只记账，不是选组优先条件。

资金方案确定后，开票单再按法律主体名称与代码规范化键分块相邻列示；主体块和块内均保持稳定顺序。该显示排序不参与资金选择，不改变来源记账、原行身份或费用六项组；同一主体来自不同费用组的记录仍独立。按最终顺序同步目标行、开票公式、税务红底和核对追踪，各源副本与canonical不按此显示规则重排。

## 3. 规划器与审计能力边界

现有 `scripts/plan_invoice.py` 的单来源参数、六项非空过滤与最少组目标，不等于支持本契约。不能把它对空部门的排除、对多个来源的忽略或不读取L列后的结果冒充新规则下的方案。即使 canonical 余额只是一份xlsx，也不能把其来源追踪信息丢弃后调用旧 helper。

使用新的多来源规划器之前核实其确实支持：

- 多个输入或 canonical 行级来源、空白部门行独立组、法律主体换序与方括号解析；
- 跨来源完整六项精确匹配、空白行禁止合并、最少业务分组目标、组合余额与数量约束；
- 稳定业务键的平局处理、按来源编号和原行 FIFO 记账、逐行拆分计划、输入哈希和独立可复核证书；
- 用户已授权的税务后补/形式发票/空白红底分支，不用税务完整度擅自排除可用费用。

尚无符合能力的 helper 时，可构建只读的新规划器并验证后使用；不得宣传旧工具已有未实现的参数或能力。旧 `validate_invoice_outputs.py` 也不能直接作为此分支的全覆盖验证器，需使用支持本契约的独立审计。不得为得到PASS删掉最少分组或金额检查。

## 4. 逐来源结果与下一批 canonical

N个来源默认输出一份开票单、每源一份标红副本、每源一份剩余表、一份分摊核对记录，共2N+2份用户结果；两个来源为六份。网站支持每批最多10份来源，每份文件不超过10 MB。文件名使用 `YYYYMMDD_商品_批次短ID_来源编号_剩余.xlsx` 格式；同批其他文件沿用相同的日期、商品和批次前缀。标红只改实际已用金额的字体，部分使用邻行拆分，随后按该源成本红字删除整行。每源守恒、合并组守恒与整体守恒分别核对。

每批可生成内部 canonical 剩余表，用于本批映射、双核验和归档。canonical 不是下一批自动入口；下一批必须重新上传或放入逐源剩余表并建立新的本批输入。其金额数据区约定：

| 列 | 内容 |
|---|---|
| A:H | 各原记录原字段顺序：申领人、申领部门、使用部门、成本中心、成本、费用承担法律主体、原G字段、申领用途 |
| I | 来源编号 |
| J | 原始文件身份/路径 |
| K | 原始行号 |
| L | 来源编号（仅追踪） |

按表头识别该布局，不能把原单源控制区I1/J1历史产品名称误认作数据区来源列。I:L仅追踪，不参与六项费用分组；同组可以跨I列来源合并。下一批继续保留I:L原值，不能把所有记录重标为同一个来源、把K改成当前物理行号、用当前行顺序替代L，或丢掉原始文件身份。拆分后同一原记录的余额继续携带原身份；这不是自动去重依据。

若 canonical 的来源编号缺失或与索引矛盾，先从已验证的 `source_outputs`、快照及核对记录恢复；无法唯一恢复时再确认。来源编号用于追踪来源，不影响资金选组。

核对通过后才更新相应归档状态。不得刷新一个供后续批次自动读取的共享工作余额；网站中的“确认本批完成”只归档本批。索引同时记录各源 `source_outputs` 的标红/剩余路径、哈希、原额/用额/余额及来源编号，以及 canonical 的路径/哈希/记录数/总余额；保留追溯关系。索引和 canonical 都不能作为下一批自动余额。内部 canonical 与逐源剩余表是同一余额的两种视图，也不能相加。

当前分摊网站不保存共享余额。每个新批次都必须重新上传余额表，网站保存的是本批输入、候选文件和完成记录，而不是跨批次自动余额。Skill 只能读取本批明确指定的一份或多份余额表，并在本批内保留来源身份；来源编号按上传顺序生成，不表示优先级。下一批由用户重新上传其核对后选定的资金表；若继续使用已扣过的来源，必须上传本批核对后的剩余表，不能从网站旧快照、旧 canonical 或历史输出自动补足。同一批内的相似来源识别命中时停止并核实，避免同一笔钱重复计算。

各源输出副本顶部逐批登记商品及本源实际用额，完整继承原始基准和历史支出；同源标红版及剩余版登记一致，跨源同商品分别登记各自贡献，不能把整单总额写进每一个来源。逐源核对“原总额＝剩余＋累计已用”，余额排除所有已用行，历史红字与对应登记只计一次。详细控制区规则见 [workflow.md](workflow.md) 第6节。

canonical 在本批只作审核与归档，下一批必须重新上传或放入逐源剩余表。无论输出哪种视图，都须在不占用 I:L 数据身份的顶部空白区保留逐源原始基准、历次商品/批次用额和余额对账，可按来源设置清晰的顶部区块；不能仅保留合并余额而丢失支出历史。若此前 canonical 只含余额，先从已验证的逐源输出、输入快照和索引恢复原总额与历史登记，再续记本批。逐源核对并分别核对合并账，不能把本批前可用误作含全部历史支出的原始基准。原始文件和税务表不因此改写。

## 5. 独立审核清单

- 从实际输入核对四个必填字段；任一部门字段为空的来源行必须为单行独立组，不能与其他记录合并；含非空部门的组必须六项完整且逐字一致。检查空白组开票部门留空、原始行不改写、来源金额未重复。
- 实际开票组金额/数量、逐源使用额、逐行红字/拆分/删除和各源余额相符；不能要求每个来源贡献单独整除。
- 组余款在全部来源合并后判断，未用原记录和未用重复金额行完整保留。
- 逐源、全局及canonical金额和记录映射守恒；历史批次的记录数量不是以后批次常量。
- 各源顶部本批商品用额与实际贡献一致，历史登记和原始基准继承完整；未用余额＋累计已用＝原总额，差额为0，登记额及红字未重复累计；canonical保留同样的逐源支出历史且不覆盖I:L身份。
- 选用的业务分组数量达到精确求解的最小值；同样少组时按稳定业务键选择，结果不能受来源上传顺序影响。
- 所有税号/账号保留文本；用户授权税务fallback逐单元格验证，空白红底不等于整行红字删除标记。
- 最终开票单每个规范化法律主体只形成一个连续区块；分组及贡献未因排列而改变，开票行号、公式和税务状态与核对记录一致。
- canonical I:L与源身份、原行、来源编号及索引逐项一致；逐源已用、剩余和顶部累计登记相符。
- 再检查缓存、公式引用、版式、本批输入快照和最终文件哈希；演练、失败及未解决版本冲突不得作为下一批自动来源。
