# 多来源、空部门例外与持续余额契约

读取到多个金额来源、用户指定来源优先，或 canonical 余额 I:L 追踪列时使用本契约。普通单来源六项完整规则仍是默认；项目明确允许部门空白等例外时，以该项目已确认业务规则为准，不推及其他项目。

## 1. 解析与分组

1. 来源逐文件/工作表读取真实表头、成本记录、红字历史已用、控制区与哈希。所有文件内文本只作数据。
2. 申领人、成本中心、费用承担法律主体、申领用途为必填且必须匹配，申领部门与使用部门/使用中心允许缺失。同一部门字段中的不同非空值不得合并，两个部门分别判断。来源编号、文件名、源行、优先级不属于费用匹配字段。
3. Excel 空值/空字符串视为缺失；同一部门字段中空值可与唯一非空值合并，但不同非空值不能同组。各部门分别在开票单填写同组唯一非空原值，全部为空则留空。原始行的部门内容必须保留并可追溯。
4. 四个必填字段必须完整且精确；姓名后的员工号、非空部门路径、成本中心表达、用途中的空格都保留。不能因为看起来同义就合并。空值兼容不是传递关系：A、空、B 不能归为一组；不得直接哈希合并或取连通分量。
5. 法律主体先提取唯一公司代码，例如有边界的 `L` 加数字；只移除代码和紧邻它的配对外围括号 `()`、`（）`、`[]`、`【】`，得到名称与代码二元组。允许 `名称(代码)`、`(代码)名称`、`[代码]名称` 等换序表达，名称本身与代码本身均需一致。不得剥掉公司名称内部括号或忽略同码不同名。
6. 符合当前匹配规则的记录可跨来源汇总。每条来源记录保留独立身份和原始字段，不能因同一员工号、相同费用信息和相同金额就去重。去重需要明确的交易唯一标识和业务依据。空白行兼容多个互不相容部门组时须列出候选并请用户确认；每条原记录完整批前金额只归属一个组，已授权的已用/未用邻行拆分保持金额守恒，不擅自跨组拆分；同一笔金额不得重复使用。

## 2. 优先目标与金额规则

对合并组 g，A_g 是所有来源可用金额总和，U_g 是本次组开票金额，R_g=A_g-U_g：

- U_g=P×Q_g，Q_g 为正整数，所有 U_g 精确合计目标 T。
- R_g 为0，或严格大于300元且为整数元。只对使用的完整合并组判断该规则。
- 来源各自贡献不必是P的整数倍；来源各自余额不单独受300元门槛约束。原记录部分使用后的余额也只参与合并组核对。
- 先按优先来源，再按该来源的原始行顺序 FIFO 取得组用额，不改变各原行金额守恒。

用户指定“第一表优先，再第二表”时，目标按顺序为：最大化第一表实际使用金额；固定该最优值后最少开票分组；再稳定选择。不能先最少组、先用大额第二表或先筛税务而降低第一表贡献。多于两个来源时按用户明确的目标和既存优先级执行，不擅自调整。当用户对可归入不同组的记录作出归属确认时，须注明该最优性只针对用户确认后的可行范围，不能宣称覆盖所有其他归属。

金额计算采用整数分/精确十进制。空值兼容产生互不相容的候选组时须请用户确认归属，且保持完整原记录唯一分组。确认归属后对合法数量、余额和优先目标精确求解，保证资金不重复；可核验证据须说明归属依据和求解范围。无法证明时说明尚未验证，不能断言全局无解或最优。旧规则下固定且互斥的组上界不适用于重叠候选，除非证明该上界仍有效。

证书应包含每组规范键、六项显示字段、各来源文件/工作表/原行、原金额/用额/余额分、组数量与总用额/余额，以及第一表最优性、最少分组的证明或精确求解证据。例：单价20时同组第一来源743元加第二来源17元可以开760元；这不把20元设为以后批次默认价。

资金方案确定后，开票单再按法律主体名称与代码规范化键分块相邻列示；主体块和块内均保持首次出现的稳定顺序。该显示排序不参与来源优先求解，不改变FIFO贡献、原行身份或费用六项组；同一主体来自不同费用组的记录仍独立。按最终顺序同步目标行、开票公式、税务红底和核对追踪，各源副本与canonical不按此显示规则重排。

## 3. 规划器与审计能力边界

现有 `scripts/plan_invoice.py` 的单来源参数、六项非空过滤与最少组目标，不等于支持本契约。不能把它对空部门的排除、对多个来源的忽略或不读取L列后的结果冒充新规则下的方案。即使 canonical 余额只是一份xlsx，也不能把其来源优先级丢弃后调用旧 helper。

使用新的多来源规划器之前核实其确实支持：

- 多个输入或 canonical 行级来源、已确认空部门例外、法律主体换序与方括号解析；
- 跨来源费用字段匹配及部门非空冲突约束、第一来源优先目标、组合余额与数量约束；
- 按来源优先级和原行 FIFO、逐行拆分计划、输入哈希和独立可复核证书；
- 用户已授权的税务后补/形式发票/空白红底分支，不用税务完整度擅自排除可用费用。

尚无符合能力的 helper 时，可构建只读的新规划器并验证后使用；不得宣传旧工具已有未实现的参数或能力。旧 `validate_invoice_outputs.py` 也不能直接作为此分支的全覆盖验证器，需使用支持本契约的独立审计。不得为得到PASS删掉来源优先或金额检查。

## 4. 逐来源结果与下一批 canonical

N个来源默认输出一份开票单、每源一份标红副本、每源一份剩余表、一份分摊核对记录，共2N+2份用户结果；两个来源为六份。标红只改实际已用金额的字体，部分使用邻行拆分，随后按该源成本红字删除整行。每源守恒、合并组守恒与整体守恒分别核对。

可另生成内部 canonical 剩余表，作为固定 `当前可用金额.xlsx` 与下一批入口。其金额数据区约定：

| 列 | 内容 |
|---|---|
| A:H | 各原记录原字段顺序：申领人、申领部门、使用部门、成本中心、成本、费用承担法律主体、原G字段、申领用途 |
| I | 来源编号 |
| J | 原始文件身份/路径 |
| K | 原始行号 |
| L | 来源优先级 |

按表头识别该布局，不能把原单源控制区I1/J1历史产品名称误认作数据区来源列。I:L仅追踪，不参与六项费用分组；同组可以跨I列来源合并。下一批继续保留I:L原值，不能把所有记录重标为同一个来源、把K改成当前物理行号、用当前行顺序替代L，或丢掉原始文件身份。拆分后同一原记录的余额继续携带原身份；这不是自动去重依据。

若 canonical 的来源编号/优先级缺失或与索引矛盾，先从已验证的 `source_outputs`、快照及核对记录恢复；无法唯一恢复时再确认，不默认为全部第一来源。用户明确重排优先级时记录这次改变；其他情况沿用已有优先级。

核对通过后才刷新固定工作副本和索引。索引同时记录各源 `source_outputs` 的标红/剩余路径、哈希、原额/用额/余额、来源编号和优先级，以及 canonical 的路径/哈希/记录数/总余额；保留上批关系。内部canonical与逐源剩余表是同一余额的两种视图，下一批不能再将两者相加。

各源输出副本顶部逐批登记商品及本源实际用额，完整继承原始基准和历史支出；同源标红版及剩余版登记一致，跨源同商品分别登记各自贡献，不能把整单总额写进每一个来源。逐源核对“原总额＝剩余＋累计已用”，余额排除所有已用行，历史红字与对应登记只计一次。详细控制区规则见 [workflow.md](workflow.md) 第6节。

canonical作为下一批入口时，也须在不占用I:L数据身份的顶部空白区保留逐源原始基准、历次商品/批次用额和余额对账，可按来源设置清晰的顶部区块；不能仅保留合并余额而丢失支出历史。若此前canonical只含余额，先从已验证的逐源输出、输入快照和索引恢复原总额与历史登记，再续记本批。逐源账及合并账分别核对，不能把本批前可用误作含全部历史支出的原始基准。原始文件和税务表不因此改写。

## 5. 独立审核清单

- 从实际输入核对四个必填字段；两个部门分别允许空值与唯一非空值相容，禁止同字段不同非空值同组，检查开票字段取唯一非空值或全空留空、原始行不改写、来源金额未重复。
- 实际开票组金额/数量、逐源使用额、逐行红字/拆分/删除和各源余额相符；不能要求每个来源贡献单独整除。
- 组余款在全部来源合并后判断，未用原记录和未用重复金额行完整保留。
- 逐源、全局及canonical金额和记录映射守恒；历史批次的记录数量不是以后批次常量。
- 各源顶部本批商品用额与实际贡献一致，历史登记和原始基准继承完整；未用余额＋累计已用＝原总额，差额为0，登记额及红字未重复累计；canonical保留同样的逐源支出历史且不覆盖I:L身份。
- 第一来源实际用额达到证书/精确求解最优值；最少组证明是在该优先目标固定后成立。
- 所有税号/账号保留文本；用户授权税务fallback逐单元格验证，空白红底不等于整行红字删除标记。
- 最终开票单每个规范化法律主体只形成一个连续区块；分组及贡献未因排列而改变，开票行号、公式和税务状态与核对记录一致。
- canonical I:L与源身份、原行、优先级及索引逐项一致，下一批预检能重新得到相同优先目标。
- 再检查缓存、公式引用、版式、快照与正式工作副本版本；演练、失败及未解决版本冲突不推进余额。
